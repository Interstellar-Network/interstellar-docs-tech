# Security Model

> **Status of this page.** This page replaces the previous Security Model. It reflects the findings of the M6 review (ORBIT-VCA-2026-001), which showed that the code and keypad displayed by the VCA pinpad can be reconstructed from captured frames. It describes only what the current release provides. It applies identically to the wallet app and to the SDK.

## 1. What the VCA pinpad guarantees, and what it does not

The pinpad provides **single-use, transaction-bound approval**: each approval challenge is generated for one transaction and is valid only within that transaction's window.

The pinpad does **not** protect the **confidentiality of what it displays**. Anything rendered for a human to perceive can be observed by a screen recorder or a camera. Dynamic visual cryptography relies on temporal integration (persistence of vision), and a recorder integrates captured frames the same way. Human readability and machine readability share one mechanism, so neither can be granted without the other.

What dynamic visual cryptography provides is narrow: a **single** frame shows only a random subset of segments, so one screenshot does not reveal the code. Any capture of several frames, or a camera, recovers the code and the keypad.

## 2. Adversarial model

| Adversary | In scope | Protection in the current release |
|---|---|---|
| Replay of a recorded approval in another session | Yes | **Mitigated**: challenges are single-use and bound to one transaction |
| Single screenshot of the approval screen | Yes | **Mitigated**: one frame does not reveal the code |
| On-device malware capturing the screen (MediaProjection, accessibility service, root) | Yes | **Not mitigated** |
| On-device malware or AI agent capturing the screen and injecting input | Yes | **Not mitigated**: it can complete the approval currently displayed |
| Overlay or clipper malware that reads the displayed code and recipient | Yes | **Not mitigated** |
| External camera with line of sight to the screen | Yes | **Not mitigated** |

MITRE ATT&CK T1410 (Screen Capture) is **not mitigated** by the pinpad.

## 3. Security properties

### 3.1 Single-use, transaction-bound approval

Each challenge is valid for one transaction and one window. A recorded interaction has no reuse value, so cross-session replay is prevented.

**Limit.** This does not protect the transaction currently being approved. An adversary that reads the live challenge can complete that approval. Device binding does not help when the adversary runs on the same device.

### 3.2 Single-frame illegibility

Each frame lights a random subset of each digit's segments, so a single captured frame does not reveal the code.

**Limit.** A per-pixel maximum or mean over a few captured frames reconstructs the code and keypad. This property offers no protection against any adversary able to capture more than one frame.

## 4. Residual risk

An adversary holding a screen-capture channel on the device (or a camera with line of sight), together with a way to enter input, can approve the transaction currently displayed without the user. In the current release, the pinpad adds no protection beyond single-use binding for that transaction.

Future designs are outside the scope of this page and will be documented only once shipped.
